# Repository review — 2026-09-27

Reviewed the server, React UI, persistence, rtorrent integration, container scripts, CI and
documentation. The working tree contains the fixes below; no new runtime dependencies were added.

## Correctness and reliability

| Finding | Correction |
| --- | --- |
| Named throttle limits used the wrong units, and small positive limits could become unlimited. | Convert the API's bytes/s to rtorrent's whole KiB/s strings, round positive limits upward, and save the actual representable value. Repair old saved groups on load. |
| Concurrent throttle edits could overwrite the other direction's limit. | Add a partial update endpoint and serialize updates per group against the latest stored values. Failed deletion retains the saved group for retry. |
| A pending recheck could restart a torrent after the user stopped it. | Serialize lifecycle changes per torrent and cancel pending restarts on subsequent explicit actions. Keep lifecycle RPCs separate. |
| A rejected throttle assignment could leave a previously running torrent stopped. | Restore its running state on assignment failure and retain the original error. |
| Completion moves could prevent startup, invoke an unsupported BusyBox flag, or leave stale file paths. | Fix nested rc quoting; introduce an argument-based move helper with collision checks; close files before moving and reopen them afterward. Use the actual on-disk base path. |
| A directory change could operate on an open torrent after its files moved. | Stop and close first, update and save the path, and leave the torrent stopped. The dialog explains the manual move and recheck steps. |
| An rtorrent crash inside a running container could leave a lock that blocked its replacement. A web-server exit was reported as a successful container shutdown. | Check stale locks before every supervised start, retain the live-process guard, and exit unsuccessfully when the web server exits unexpectedly. |
| Deletion checks only covered lexical paths. | Check canonical paths and existing ancestors before erasing metadata and again before deleting data. Refuse symlink escapes and deleting a configured root or its ancestor. |
| Malformed fields in otherwise valid state JSON could break unrelated persisted data. Failed writes could discard the dirty flag. | Repair individual fields, retain valid siblings, retry failed writes, return copies of mutable state, and avoid dirtying the store for identical writes. |
| Concurrent snapshots could duplicate expensive reads or prune counters using a filtered torrent list. | Share in-flight reads; fold and prune only complete session snapshots, before unrelated awaits. |
| Concurrent URL additions could satisfy each other's confirmation. | Serialize additions through the service. Uploaded files and magnets are confirmed by their own hash. |

The named throttle conversion follows the setters in
[rtorrent's command implementation](https://github.com/rakshasa/rtorrent/blob/v0.16.24/src/command_throttle.cc).
Real setter/getter round trips are included in the smoke script so fake clients cannot hide unit errors.

## Validation and protocol handling

- Validate whole batches before mutation, normalize and deduplicate hashes, and reject coercible
  objects, nulls, malformed booleans and out-of-range integers with field-specific errors.
- Validate all per-torrent patch fields before applying any of them. Reject malformed RPC parameter
  arrays and log-scope lists instead of silently turning them into empty requests.
- Bound the combined buffered upload size, including chunked requests, and limit the combined
  file/URL count. Return failed item indices so retries retain only unsuccessful submissions.
- Validate bencode structure, dictionary ordering, metadata, piece counts and paths; derive hashes
  from the exact info bytes. Decode magnet topics correctly and explain unsupported v2-only files.
- Reject malformed XML nesting and typed values; preserve struct keys as data, including
  `__proto__`; reject non-finite outgoing numbers.
- Bound SCGI response size and total request time, including a peer that keeps sending a trickle
  of data. Report backend transport/protocol failures as HTTP 502.
- Compare the complete browser origin, including scheme and port. Keep root health checks working
  under a base path, redirect the base document to its trailing slash, and return 404 for missing assets.
- Validate numeric environment settings and render startup JSON from the option catalog, preserving
  quoted values. Skip persisted log scopes unsupported by the selected rtorrent version.

The server dependency minimums were raised to Express 4.22.3 and Multer 2.4.0. This includes the fix
for the published [Multer multipart crash advisory](https://github.com/expressjs/multer/security/advisories/GHSA-wc9g-mqfw-jrwm)
and resolves the affected transitive query-string parser versions described by the
[qs advisory](https://github.com/ljharb/qs/security/advisories/GHSA-4mjr-xmp4-gh2g).

## UI and performance

- Preserve edits made while preferences load; serialize saves, coalesce newer edits, and retry after
  failure or reconnect. Repair invalid cached preferences before first paint.
- Ignore stale detail and dialog responses after changing torrents, tabs or requests. Protect local
  detail edits from an older poll. Prevent duplicate form submissions and prevent completed actions
  from closing a newer dialog.
- Stop hidden-tab polling timers. Keep table columns stable when live values change. Use fixed
  percentage column widths and scroll wide details inside their own pane.
- Fix mobile header crowding and retro-theme overflow at 360px. Keep expanded details readable at
  the left edge of wide tables. Hide the closed drawer from keyboard navigation.
- Make peer/tracker expansion keyboard operable, label compact icon buttons, and respect disabled
  fieldsets in focus trapping. Cancel pending in-app prompts when their provider unmounts.
- Redact tracker secrets in errors, toasts and console output, including encoded token names.
- Correct duration rounding and rate parsing/formatting; preserve byte precision in rate inputs.
- Clean up long-press timers, accept supported dropped links consistently, preserve text-field drops,
  and respect the gamification flag for drop effects.

## Structure and documentation

- Share HTTP types in `server/src/contracts.ts` and the pure preference schema in `server/src/prefs.ts`.
  The browser consumes the same types and allowlists. Unsupported settings remain optional in its type.
- Extract validation, deletion-path checks, throttle conversion, bounded uploads, startup settings,
  mutation queues and pending restart state from larger modules. Keep the browser preference sync
  independent of DOM globals so it can be exercised by the node runner.
- Document actual API paths, multipart field names, upload results, limits, throttle precision,
  directory changes, completion moves and the updated module boundaries in README and AGENTS.
- Test release-bump failures, documentation drift, literal User-Agent replacement and completion
  move collisions in `docker/scripts.test.sh`; run it in every Docker build and CI.
- Run the real settings/throttle smoke checks in CI and release jobs. `make smoke` uses the same
  script and gracefully removes its disposable container even after a failed check.
