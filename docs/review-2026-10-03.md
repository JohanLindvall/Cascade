# Repository review — 2026-10-03

Reviewed the Go server, XML-RPC/SCGI transport, rtorrent integration, state store, stream,
React UI, container scripts, build workflows, tests and documentation. No runtime dependencies
were added.

The starting working tree already contained changes to deletion confinement, atomic state writes,
load-directory validation, throttle names and settings patches. Those changes were preserved and
reviewed, including their regression tests. The settings helper initially imported its type from
the wrong module, preventing the web build; that import is corrected. The pre-existing
`server/package-lock.json` was left untouched.

## Additional corrections

| Finding | Correction and verification |
| --- | --- |
| A listing delayed across an erase could recreate forgotten bookkeeping and count the removed torrent's traffic twice. | Order listing reads and store updates with erases using a cancellable gate. Deterministic concurrency tests cover the stale listing and cancellation while waiting behind an erase. |
| A fast rtorrent restart entirely between ticks retained the previous process's capability table. | Invalidate capabilities when the PID changes, before restoring startup settings. A regression changes the command table without simulating a connection failure. |
| Preference edits queued as an earlier flush finished could remain unsent even after a successful flush promise. | Recheck pending edits after awaiting the shared write; test both an empty flush followed by an edit and an edit queued as a write completes. |
| A failed initial preference read left the browser cache authoritative for the whole visit. | Retry the read and wait for saved badge preferences before announcing badges. Browser request interception verified recovery from an initial 502 and replacement of a stale cached theme. |
| Late file edits or tracker additions for an earlier torrent could invalidate the next torrent's pending detail read. | Check the current torrent/tab before changing request generations or applying an edit. Browser tests hold both requests, release the old mutation first, and require the new details to render before the next poll. |
| Tracker grouping never retried failures or noticed trackers added to an existing torrent. | Extract `useTrackerHosts`, key it on hashes and tracker counts, and retry failed reads. Successful reads incur no further requests until those inputs change. Browser checks cover an initial failure and adding a first tracker. |
| A mobile checkbox opened full-screen details, interrupting bulk selection. | Separate selection and detail focus rules in `app/rowFocus.ts`; test modifier selection and verify multiple checked cards without an open sheet. |
| Compact drawers and detail sheets left keyboard focus behind them. | Share responsive focus handling, trap Tab, restore the opener and handle Escape. Make drawer visibility immediate on opening so focus succeeds during its slide animation. Browser checks cover wrapping, closing and opening a tool from the drawer. |
| Dialogs painted underneath an open mobile details sheet. | Put the modal layer above drawers, details and menus. Verify the topmost element at the viewport centre and inspect the resulting screenshot. |
| Passwords containing an additional `@` leaked their suffix in displayed URLs. | Mask userinfo through the final `@` in the authority; test both individual URLs and log text. |
| An oversized later upload part could consume another file-sized allocation before the batch was rejected. | Read only the remaining batch allowance plus one byte. A chunked-body regression verifies early refusal with bounded read-ahead. |
| An unexpected HTTP serving failure skipped the normal drain and final state flush. | Use the same shutdown path for signals and serving failures, and flush on every exit while retaining the original error. |
| The same browser-compatible malformed UTF-8 decoder existed in two Go packages. | Move it and its combined regression cases into `internal/utf8text`, shared by XML-RPC and torrent metadata/magnet parsing. |
| Log scope instructions promised that restarting rtorrent would disable scopes baked into the generated rc. | Explain that a container restart regenerates the rc and reliably removes those scopes. Update UI messages, README and maintainer guidance. |
| The smoke container's creation omitted the documented shutdown timeout. | Set `--stop-timeout 60`, consistent with its graceful cleanup. |

Documentation also follows the renamed focus module, explains the listing/erase ordering,
describes rooted deletion accurately, and avoids claiming that a finite filename hash guarantees
collision freedom.

XML-RPC decoding, 2.42 ms for decoding plus mapping, and 0.39 ms for stream diffing. These are local
measurements, not comparative speedup claims. The changes retain shared reads, memoized rows and
tabs, and the existing dependency limits.

image validation ran on linux/amd64; ARM images, other browser engines and a full swarm transfer
were not exercised in this pass. Temporary logs, browser scripts and screenshots are in
`/tmp/cascade-deep-review/` on the review machine.
